# HANDOVER 2026-05-21

## DLNA and Offline VR Naming Update

- Read `PROJECT.md` and inspected the DLNA/offline naming paths.
- Added centralized VR filename logic in `utils/vr_naming.py`.
  - Known player marker detection now lives in one place.
  - Marker set covers HereSphere-style suffixes such as `LR/RL/TB/BT/2D/3D/3DV/F180/180F/FISHEYE190/RF52/MKX200/MKX22/VRCA220/EAC360/360EAC/ALPHA`, full-frame variants such as `LRF/RLF/TBF/BTF/SBSF/OUF`, and SKYBOX-style aliases such as `SBS/HSBS/HOU/Half SBS/Half OU/Left Right/Top Bottom`.
  - Supported separators are underscore, space, and ` - `, matching the player suffix convention.
- Corrected source-video interpretation:
  - Plain 2D videos are width:height < 2:1 and keep their original DLNA title.
  - 2:1 half-equirectangular / VR180 source videos without known player markers are virtually displayed as `source_SBS_180`.
  - Existing VR/player markers prevent automatic `_SBS_180` injection.
- Updated DLNA names:
  - Raw media title uses `source_display_stem()` so only unmarked 2:1 sources get `_SBS_180`.
  - Green live virtual title is based on the displayed source stem, e.g. `movie_SBS_180_passthrough_live`.
  - Alpha live virtual title is based on the original source stem and uses `F180` + SBS markers, e.g. `movie_SBS_F180_alpha_live`.
  - `FISHEYE` in alpha source names is rewritten to `F180` before appending the alpha suffix.
  - Bumped `dlna/content_directory.py` DIDL schema version from 4 to 5 to avoid stale client/catalog cache.
- Updated offline output naming:
  - `offline/convert.py`, `tools/offline_passthrough.py`, and `tools/offline_alpha_passthrough.py` now call `utils.vr_naming`.
  - Green offline defaults:
    - 2:1 unmarked source: `source_SBS_180_passthrough.mp4`
    - normal 2D source: `source_passthrough.mp4`
  - Alpha offline defaults: `source_SBS_F180_alpha.mp4`.
- Updated offline-output detection to recognize the new suffixes while keeping legacy suffixes.
- Added/updated tests:
  - `tests/test_vr_naming.py`
  - `tests/test_content_directory_modes.py`
  - `tests/test_offline_convert.py`
  - `tests/test_offline_outputs.py`

## Follow-up Fix: Dotted Source Stems

- Fixed `utils/vr_naming.py` so dotted source stems are not truncated.
  - Bug example: `xxxx.com@atvr00067_1_8k.mp4` was passed as `path.stem`, then parsed again with `Path(...).stem`, which incorrectly reduced it to `xxxx`.
  - Added `_as_stem()` to strip only known video file extensions and preserve dots inside already-derived stems.
- Added a regression test for `xxxx.com@atvr00067_1_8k`.

## Follow-up Fix: Explicit Extension Parsing

- Reworked `_as_stem()` again to avoid relying on `Path.suffix` / `Path.stem`.
  - It now explicitly takes the substring after the final dot as the extension candidate.
  - Only known video extensions are stripped.
  - The remaining base name is then checked for VR/player suffix markers using the configured valid separators.
- Confirmed that dot is not treated as a VR suffix separator. Example: `scene.F180` does not count as a valid `_F180` marker and a 2:1 source becomes `scene.F180_SBS_180`.

## Follow-up Fix: Marker Separators

- Narrowed VR/player marker separators to underscore and hyphen only.
  - Spaces are no longer valid separators.
  - `scene F180` and `scene - F180` are not treated as valid player markers.
  - Hyphenated forms such as `scene-F180`, `scene-Half-SBS`, and `scene-Top-Bottom` remain valid.
- Updated `tests/test_vr_naming.py` to cover the separator behavior.
