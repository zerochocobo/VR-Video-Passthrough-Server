# HANDOVER 2026-08-08

## VR 转平面前向投影超采样的性能优化

### 背景

`d989015`（VR投影修复，适配训练模型）给 `to_flat()` 加了自动超采样，修掉了近极带欠采样导致的摩尔纹/混叠——画质问题确实解决了，但实时 VR 去码的 FPS 明显下降。实时与离线走同一份 `GpuRmProcessor.process_chunk()`，所以两边都受影响。

根因不是超采样本身，而是它的实现方式，配合调用次数被放大：`process_chunk` 对每个区域的 8 帧各调一次 `to_flat`（2 个区域即 16 次/chunk），而每次调用里有三笔本可避免的开销。8K 实测：

| 项 | 单次开销 | 说明 |
|---|---|---|
| `_source_footprint` | 0.5–0.7 ms | 纯 CPU；视角在整个 chunk 内不变，却每帧重算 |
| `big` 缓冲 + `.mean()` 降采样 | 0.3–0.6 ms | S=8 时 12.6 MB 临时缓冲写完再读一遍；`mean` 默认走 float64 |
| `cp.asarray(R)` H2D | 0.054 ms | 角度不变，每 chunk 传 32 次（`to_flat` + `blend_into`） |

真实片源上自动选中的 S 实测为 6~8（`test_demosaic_1143_8k.mp4` 为 6/7，`test_demosaic_1.mp4` 为 8），正好落在最贵的一档。

### 本次完成

- 新增 CUDA kernel `equirect_to_flat_ss_u8`：把 S×S 的采样直接在寄存器里累加，一个线程产出一个输出像素。采样位置与"渲染 S 倍大图再盒式降采样"逐点相同，但不再需要临时缓冲和第二遍显存往返；取整发生在平均之后（比原先先取整后平均略微更正确）。
- 抽出 `__device__ sample_eye()`，原 `equirect_to_flat_u8`（S=1 快路径）与新 kernel 共用同一份采样代码，投影数学未改动。
- 新增 `VrReprojector._ss_cache`：`_source_footprint` 结果按视角记忆化。key 量化到 0.5°——S 是取整的阶梯值，半度最多让它移动一档，这样每帧视角都在漂移的调用方（美颜跟踪移动的人脸）也能命中，而不只是视角固定的 RM 路径。实测 64 次 `to_flat` 只需算 6 次 footprint。
- 新增 `VrReprojector._rot_g()`：旋转矩阵按角度缓存并复用于 `to_flat` / `to_equirect` / `blend_into` / `blend_into_masked`，消除每次调用的 H2D 拷贝。两个缓存都在超过 512 条时整体清空。
- 更新 `_source_footprint` 上方的 REVIEW NOTE，说明融合累加与记忆化的原因，避免后续再退回临时缓冲写法。

- `pipeline/vr_reproject.py`（唯一改动文件）

### 验证

RTX 5060 Ti，8K SBS 片源。

单次 `to_flat`（auto，GPU 空闲）：

| 视角 | 旧 | 新 |
|---|---|---|
| equator | 0.836 ms | 0.019 ms |
| mid | 0.866 ms | 0.053 ms |
| pole-band | 0.872 ms | 0.305 ms |

端到端 `process_chunk`（8K，2 区域）：**81.7 → 75.7 ms/chunk（97.9 → 105.7 fps，+7.9%）**。相对完全不做超采样的基线，超采样溢价从 5.4 ms 降到 3.2 ms/chunk。端到端收益小于单次调用收益之和，是因为部分 CPU 时间本就能与 GPU 重叠；实时管线里解码/编码同样在抢 CPU，那边的实际改善应更接近单次调用的账。

正确性：
- `to_flat` 与旧实现逐像素对比，S=2/4/8 三档最大差 **1 LSB**（即"先平均后取整"与"先取整后平均"的差别）。
- 整帧端到端（8 帧 8K）最大差 4、均值 0.0028，为该 1 LSB 差异经反投影双线性放大的结果，视觉无差别。
- 缓存 key 量化到 0.5° 后输出与量化前完全一致，说明未改变实际选中的 S。

用户已实机测试，实时 VR 表现"尚可"。

### 后续建议

- pole-band 剩余的 0.24 ms 就是 64 taps kernel 本身，是画质修复的真实成本，除非降 S 否则去不掉。
- 曾评估按轴各向异性采样（sx×sy 取代 S²）：实测真实近极带两轴拉伸都在 10~13 倍，只有中纬度（4.6 vs 3.0）有收益，不值得该复杂度，已否决。
- 若实时仍然吃紧，最直接的旋钮是把 `MAX_SUPERSAMPLE` 提为 config 项，实时用 4、离线用 8。
