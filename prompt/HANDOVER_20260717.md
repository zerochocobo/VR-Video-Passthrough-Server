# HANDOVER 2026-07-17 — NEWUI branch: Home page refactored into navigation rail + feature cards

## Background

The old home page placed every feature into fixed-height configuration rows inside three collapsible sections (one 34 px row per feature), making further expansion impractical. On the NEWUI branch, it has been refactored into a left-side brand navigation rail and a feature-card grid on the home page, so the window no longer reshapes when sections are expanded or collapsed.

## New layout

- **Navigation rail** (`ui/widgets/nav_rail.py`, 92 px, icons + labels, navy background):
  Home / Offline Tools / Subtitle Style / Logs / Settings (at the bottom). The logo is at the top.
- **Home page** (`ui/pages/dashboard_page.py`): server control bar (large Start/Stop button + address + live FPS/VRAM status) plus a feature-card grid, grouped as “Live Output” and “Audio & Subtitles”. Each card contains an icon, name, toggle, one-line status summary, and a gear button that opens the original configuration dialog. To add a feature, add one card (three columns with automatic wrapping).
- **Offline Tools page** (`ui/pages/tools_page.py`): three tool cards leading to the original OfflinePage / TwoDvrPage / RmPage (their Back buttons return to this page).
- **Settings page** (`ui/pages/settings_page.py`): media directory, language, performance settings (quality/FPS/output size/TensorRT), and **feature debug status** (visibility toggles for features under development; currently includes the “Remove Mosaic” card, settings key `rm_card_visible`, disabled by default).
- **Logs page** (`ui/pages/log_page.py`): log view + debug-mode toggle + Clear button + Report a Problem button.

## Brand colors

Taken from `resources/logo.png` (new, copied from `assets/logo_transparent.png`): navy border `#013E71`, blue `#0189F4`, and green `#44B648`. Constants are defined in `ui/theme.py`.

Line icons are unified in `ui/icons.py` (drawn with QPainter and shared by the navigation rail and cards).

## Notes

- For a custom QWidget subclass to apply stylesheet backgrounds, `setAttribute(Qt.WA_StyledBackground, True)` is required (this affected NavRail).
- `tests/test_settings.py::test_passthrough_mode_mapping` was an existing failure (the default `mode_two_dvr` was `True` but had not been updated), unrelated to the refactor. It was fixed that day (all eight two_dvr combinations are covered; see below).
- Behavioral equivalence retained: SI/RM/Light Match toggles still issue immediate PUT requests to the running server; Green Screen/Alpha/2DVR/Subtitle toggles still take effect as environment variables when the server starts.

## Same-day addition: DLNA name/port settings + scrolling settings page

- Added a “DLNA Server” group to the settings page: server name (blank = server default `VR Passthrough Server`; `PT_SERVER_NAME` is sent only when non-blank) + HTTP port (1024–65535; invalid values fall back to 8200; sent as `PT_HTTP_PORT`). Changes are concentrated in `ui/settings.py` (`DEFAULT_HTTP_PORT`/`DEFAULT_SERVER_NAME`, `http_port()`/`server_name()`, `server_env()`) and `ui/pages/settings_page.py`.
- Port propagation to the UI itself: `MainWindow.__init__` and `toggle_server` write the port to the UI process’s `os.environ["PT_HTTP_PORT"]`. The dashboard address, runtime-status polling, and live-control PUTs all read this environment variable, ensuring they always target the actual server port (changing the port on the settings page requires a server restart; comments in the group explain this).
- The settings-page body was changed to a `QScrollArea` (when groups exceeded the window height, fixed row heights were compressed and controls overlapped; this issue has been encountered and resolved). Add future settings groups directly to `scroll_body`.
- The existing `test_passthrough_mode_mapping` failure was fixed (all two_dvr combinations covered); three DLNA-related tests were added. All 21 tests in `tests/test_settings.py` pass.

## Same-day addition 2: Explicit Save button for DLNA configuration

Users reported that they “could not see a Save button and did not know when the name would take effect.” The original implementation silently saved on `editingFinished` (focus loss or Enter). It was changed as follows:

- Added a **Save button** inside the DLNA group. It is enabled only when the name or port differs from the saved value (dirty). After a successful save, the button is disabled and a green message says “Saved. Restart the server for the changes to take effect” (automatically disappears after four seconds; i18n key `settings.dlna_saved`). Editing again immediately clears the message and re-enables the button.
- Automatic save on focus loss is retained as a fallback (changes are not lost when switching pages immediately); the Save button provides deterministic feedback.
- `_dlna_dirty()` compares against the values stored in settings rather than tracking whether a field was edited; restoring the original value automatically disables the button.

Other miscellaneous changes that day: the RM card title on the Offline Tools page now uses the dedicated key `tools.rm_title` (“Offline Remove Mosaic”) instead of the generic `rm.offline_generate`; the version was raised to v1.2.0.
