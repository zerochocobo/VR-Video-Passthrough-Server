# HANDOVER 2026-06-29

## SAM3 / MatAnyone2 offline prepass OpenCV CPU OOM

- User report:
  - SAM3 + P7 + RTX 5080 offline alpha/passthrough conversion crashed near the end of SAM3 prepass.
  - Log ended at `SAM3 prepass 3761/3839 ... gpu=12535/16303MiB`.
  - Traceback failed in `offline/decoded_frames.py: decoded_frame_to_bgr()` with OpenCV unable to allocate `88473600` bytes.
- Diagnosis:
  - The traceback is still inside the SAM3 prepass child process, before MatAnyone2 propagation and before NVENC/P7 output encode.
  - `88473600` bytes equals a full 7680x3840 BGR frame allocation, so the immediate failure is CPU/OpenCV contiguous memory allocation, not SAM3 CUDA VRAM exhaustion.
  - Previous prepass flow materialized full-width SBS BGR, then allocated two RGB eye copies. For 8K SBS this creates avoidable large CPU temporaries and can fail late after thousands of samples.
- Fix implemented:
  - `offline/decoded_frames.py`
    - Added `_decoded_frame_planes_to_nv12_cpu()`.
    - Kept `decoded_frame_to_bgr()` compatibility.
    - Added `decoded_frame_to_sbs_eye_rgbs()` to convert NV12/P016 directly to left/right RGB eyes without full-frame BGR.
    - Added `scene_bgr_from_rgb()` to downsample before RGB->BGR conversion for scene detection.
  - `tools/offline_alpha_passthrough.py` and `tools/offline_passthrough.py`
    - SAM3 prepass now uses direct SBS eye RGB conversion.
    - Explicitly releases decoded frame, ONNX `image_out`, eye images, mask locals, and temporary mask tensor locals at each sample.
  - `offline/yolo26m_efficientsam.py`, `offline/yolo26m_birefnet.py`, `offline/yoloworld_efficientsam.py`
    - Replaced the same full-frame BGR prepass conversion path.
- Tests:
  - Added `tests/test_decoded_frames.py`.
  - Passed:
    - `.venv\Scripts\python.exe -m pytest tests/test_decoded_frames.py`
    - `.venv\Scripts\python.exe -m pytest tests/test_yolo26m_efficientsam.py tests/test_yolo26m_birefnet.py`
    - `.venv\Scripts\python.exe -m pytest tests/test_offline_convert.py tests/test_matanyone2_trt_runtime_paths.py`
  - AST parse check passed with `encoding="utf-8-sig"` because `tools/offline_alpha_passthrough.py` has a UTF-8 BOM.
- Notes:
  - Initial `python -m pytest` used system Python 3.13 and failed because `cv2` was not installed there; reran with project `.venv` Python 3.12 successfully.
  - `git diff --check` passed. Git emitted line-ending warnings only.

## DLNA video directory UNC path restriction

- User request:
  - Home page DLNA video directory binding should reject UNC network share paths starting with `\\` / `//`.
  - DLNA should use local paths only, including cloud-drive mounts that appear as local drive letters or local directories.
- Fix implemented:
  - `media_library.py`
    - Added `is_unc_path()` to detect ordinary UNC shares and extended UNC paths.
    - `parse_video_dirs()` now skips UNC roots and falls back to the default local `videos` directory if every configured root is invalid.
  - `ui/settings.py`
    - `video_dirs()` and `set_video_dirs()` filter UNC entries before saving or building `PT_VIDEO_DIR`.
  - `ui/dialogs/video_dirs_dialog.py`
    - Existing UNC entries are hidden from the dialog list.
    - New UNC selections are blocked with a warning instead of being added.
  - `ui/translations/{zh_CN,en_US,ja_JP}.json`
    - Added localized warning text for blocked UNC paths.
  - Tests updated:
    - `tests/test_media_library.py`
    - `tests/test_settings.py`
    - `tests/test_ui_smoke.py`
