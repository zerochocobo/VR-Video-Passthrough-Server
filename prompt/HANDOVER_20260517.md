- Reason: `ThreadedDecoder` brought alpha passthrough flicker/stability issues and did not show enough steady-state benefit beyond startup speed.

  - offline single conversion
  - offline batch conversion
- Replaced them with "Quality / Speed / 画质速度":
  - `ultrafast` -> `PT_PASSTHROUGH_PYNV_PRESET=P1`
  - `medium` -> `PT_PASSTHROUGH_PYNV_PRESET=P4`

- Offline conversion no longer defaults to P5/P7:
  - `offline/convert.py` default preset uses `config.PASSTHROUGH_PYNV_PRESET`.
  - `tools/offline_passthrough.py` and `tools/offline_alpha_passthrough.py` direct CLI defaults also use `config.PASSTHROUGH_PYNV_PRESET`.

## Short DLNA live item green/alpha mode fix

- Bug: for videos shorter than the live chapter threshold, DLNA exposes live passthrough as direct virtual files instead of virtual chapter folders. When green and alpha were both enabled, some clients could treat both short virtual files as green.
- Root cause: short virtual file ids (`lg_...` / `la_...`) were not recognized by `_id_to_live()` / `BrowseMetadata`; only long-video chapter container ids (`pl_...` / `pla_...`) were mode-aware. A client that re-browsed metadata by item id could lose `mode=alpha`.
- Fix:
  - Added explicit short live item prefixes `lg_` and `la_`.
  - `_id_to_live()` now recognizes both short item ids and long chapter container ids.
  - Short live items now carry `passthrough_mode`.
  - `BrowseMetadata` returns item metadata for short live items, preserving `?mode=green` / `?mode=alpha`.
- Validation:
  - Added tests for distinct short live ids/URLs and alpha metadata.
  - `python -m unittest tests.test_content_directory_modes` passed.
  - `py_compile` passed for `dlna/content_directory.py` and the updated test.

## Main UI runtime FPS/VRAM status

- Added `GET /runtime_status` on the main media server.
  - Reports whether a passthrough stream is active, current source name/path, configured output FPS, produced FPS estimated from `frames_produced / elapsed`, frame/byte counters, and GPU VRAM used/total in MiB.
  - VRAM query uses `nvidia-smi` from `PATH`, then falls back to `%SystemRoot%\System32\nvidia-smi.exe` / `%WINDIR%\System32\nvidia-smi.exe`; no hard-coded `C:\Windows` path remains.
  - Active stream start time is tracked alongside `_active_streams` and preserved when a placeholder stream is replaced by a live session.
- Added a centered runtime status label to the main window status bar.
  - Starts polling only after the server process is marked running.
  - Stops polling and clears the label when the server stops.
  - Displays VRAM while the server is running; when a video is active, prefixes current FPS.
  - Polling runs in a daemon background thread and emits back to Qt via a signal, avoiding UI blocking.
- Added `status.vram` translation key to `zh_CN`, `en_US`, and `ja_JP` JSON files; files remain readable as UTF-8-BOM.
- Validation:
  - `python -m py_compile http_app\routes_media.py ui\main_window.py` passed.
  - Translation JSON parse check confirmed `zh_CN status.vram == 显存`.

## Server start/stop button pending-state guard

- Improved main UI server button interaction to prevent rapid repeated start/stop clicks before the next `QProcess` state transition arrives.
- `MainWindow` now tracks `_server_action_pending`:
  - start click disables the server button until startup reaches `listening` or fails/exits;
  - stop click disables the button until the process exits;
  - startup cancel also enters the stopping pending state.
- `ServerProcess` now listens to `QProcess.errorOccurred` and emits a stopped state when startup fails before normal process state changes, so the button is restored instead of staying disabled.
- Validation: `python -m py_compile ui\main_window.py ui\services\server_process.py` passed.
