# HANDOVER 2026-06-24

## CloudDrive2 / Y Drive Path Resolve Fallback

The user reported that setting the Home media directory to `Y:\` failed with:

`skip unusable media directory Y:\: [WinError 1005] The volume does not contain a recognized file system.`

Background: `Y:` is the virtual drive root mounted by CloudDrive2. Calling `Path.resolve()` on that root can raise `WinError 1005`. Following the same class of fix in `G:\GIT\debug\VR_Video_Toolbox\tool_dlna`, this repository now falls back to `os.path.abspath()` when path resolution fails.

## Changes

- `media_library.py`
  - Added `safe_resolve_path(path)`, returning `Path(os.path.abspath(...))` when `Path.resolve()` fails.
  - `parse_video_dirs()` no longer skips virtual drive directories that raise `WinError 1005`.
  - `build_media_roots()`, `MediaLibrary.path_to_key()`, `key_to_path()`, and `contains()` now use `safe_resolve_path()` consistently.
  - `key_to_path()` keeps the root containment check to prevent `..` escapes.
- DLNA/HTTP playback path code now uses the shared resolver:
  - `dlna/content_directory.py`
  - `http_app/routes_media.py`
  - `http_app/si_stream.py`
  - `utils/media_index.py`
  - `utils/subtitles.py`
  - `pipeline/subtitles.py`
  - `utils/cache_key.py`
  - `utils/bitrate_estimator.py`
  - `pipeline/pynv_stream.py`
  - `pipeline/pynv_io.py`
- `tests/test_media_library.py`
  - Added/adjusted regression tests that simulate `OSError(1005, ...)`, confirming `Y:\` is kept as an absolute path and `MediaLibrary` key round-tripping still works.
