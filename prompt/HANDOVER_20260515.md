# Handover 2026-05-15

## DLNA SQLite Index Hardening

- Hardened the SQLite-backed DLNA media index in `utils/media_index.py` for future schema and operational edge cases.
- Added explicit schema handling:
  - `SCHEMA_VERSION` is mirrored into both `meta.schema_version` and SQLite `PRAGMA user_version`;
  - startup validates required tables/columns;
  - future/newer schema versions are treated as incompatible and rebuilt instead of being silently overwritten;
  - `_migrate_schema()` now exists as the forward migration hook for future field additions.
- Added database recovery:
  - corrupt or incompatible `library_index.sqlite` files are moved aside with a `.corrupt_YYYYMMDD_HHMMSS` suffix;
  - related WAL/SHM files are also handled;
  - if a database operation fails during Browse, the index rebuilds and retries once.
- Added Windows-specific safety after testing:
  - `_open_connection()` now closes a partially opened sqlite handle if PRAGMA setup fails, avoiding locked corrupt files that cannot be renamed.
- Added SQLite operational guardrails:
  - connection timeout and `busy_timeout` are set;
  - stale-entry deletion now uses a temporary table instead of a long `NOT IN (?, ?, ...)` list, avoiding SQLite parameter-count limits in large directories.
- Added scan edge-case protections:
  - directories outside configured media roots are rejected cleanly;
  - large directory scans are logged for diagnostics;
  - newly modified video files are marked `pending` for a short grace window before probing, reducing ffprobe work while files are still being copied;
  - pending probes retry after 2 seconds, real probe failures retry after 60 seconds;
  - per-directory probe failure logging is capped to avoid log floods from many bad files.
- Validation:
  - `python -m compileall config.py utils\media_index.py dlna\content_directory.py` passed.
  - Normal cache smoke test passed: repeated Browse hits the same snapshot; adding a file changes the signature and returns the new file.
  - Corrupt SQLite file test passed: bad DB is moved aside and rebuilt.
  - Future schema version test passed: `user_version=999` DB is treated as incompatible and rebuilt.
  - Large directory test with 1100 child directories passed, covering the previous SQLite parameter-limit risk.
