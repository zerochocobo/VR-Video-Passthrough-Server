## DLNA 外挂字幕兼容性研究与改造（完成）

- 用户要求核实 Samsung CaptionInfo/CaptionInfoEx、额外 res 和同名 SRT 发现方案，并据实改造。
- 当前代码已支持同目录 SRT/ASS/SSA/VTT、语言后缀、SEC 标签、`/subs` GET/HEAD 和视频 `CaptionInfo.sec` 头；外挂发现独立于实时烧录开关。
- 已核实 Kodi 官方源码采用 SEC、额外字幕 res、视频 res 的 `pv:subtitleFileUri`/`pv:subtitleFileType`；MiniDLNA 源码对 LG 使用 `text/srt`，对三星使用 SEC/HTTP caption。
- UPnP ContentDirectory:4（2013）已有 `upnp:resExt` 的 Caption/Subtitle 组件和外部 SRT 资源示例，因此“协议从未定义外挂字幕”过于绝对；客户端普遍兼容不能从服务端元数据直接推断。
- 明确发现：媒体索引签名忽略字幕文件，新增/删除字幕可能无法使 DIDL 目录缓存失效；普通视频 ObjectID 的 BrowseMetadata 未解析，可能返回根目录元数据。
- 开始工作时另有离线 VR 模式相关未提交修改；期间已在同一工作区由原任务提交为 8f2734b。本任务保留上方交接内容及该提交，不覆盖或重复提交离线改动。

### 实现

- utils/media_index.py：字幕的文件名、大小、mtime 纳入目录签名，创建/修改/改名/删除均使 DIDL 缓存重新生成；字幕不作为独立视频条目列出。
- utils/subtitles.py：同目录、同 stem 与语言后缀改为不区分大小写的字面匹配，修复方括号被 glob 当作模式的问题；保留媒体根目录边界检查。默认单链接优先 SRT，列表的无语言后缀/中文/英文排序保留。
- dlna/content_directory.py：保留每条字幕的原 MIME res，并为 SRT 追加 `text/srt` 兼容 res；原视频 res 上增加 PV 字幕 URI/类型；SEC 两标签只输出一套默认字幕，避免多字幕时无语言标签导致默认不确定。所有链接与 HTTP caption 使用同一个选择规则。
- SRT 兼容 URI 使用 `/subs/...srt?mime=text/srt`，原 URI 仍是 application/x-subrip；GET/HEAD/Range 均按 URI 实际输出对应 MIME，保留原始字节，不虚报 UTF-8 charset 或自动转码。
- 普通视频 `v_` ObjectID 的 BrowseMetadata 返回视频本身及字幕；支持旧无版本和 ptv 版本格式。DIDL schema 从 11 升至 12，促使客户端重新获取变更后的元数据；现有测试改用当前版本构造期待值，旧 ID 解析测试保留。
- dlna/connection_manager.py：GetProtocolInfo 补齐 SRT 两种 MIME、ASS/SSA/VTT。
- http_app/routes_media.py：视频 GET/HEAD/Range 统一返回默认 `CaptionInfo.sec`；移除错误的响应 `getCaptionInfo.sec`（它是客户端请求头）。字幕非法或越界 Range 返回 416 和正确 Content-Range，拒绝与实际格式不符的 MIME 覆盖。
- README 三语增加同名/多语言字幕使用方式、缓存刷新、烧录开关独立性、原始编码和客户端能力边界；UI 未变动。
